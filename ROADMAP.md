# Roadmap

Each milestone ends with a verifiable exit criterion.

| Milestone | Content | Exit criterion |
|---|---|---|
| **M0 — Foundations** | Repository hygiene (CI on Windows, macOS and Linux, dependency checks, licence), CLI skeleton, `foedrum doctor`, event store (local index + state branch), fold, multi-repository data model (orders, sub-orders, dependencies), batch state machine, supervisor (leases, deadlines), fake brewer runner, property tests and chaos tests | 1,000 chaos runs with random engine kills: no lost or duplicated side effects, no silent stalls |
| **M1 — First pour** | Polling intake, Nip recipe (test-first: Gauger and red proof), `claude` CLI runner, command layer, Claude Code plugin with `/foedrum:brew`, `status`, `stuck`, `answer` and `resume` (same machine), batch leases for the two drivers, worktrees from local clones, gravity readings, open pull request, status comment | A real issue in a test Brewery becomes a pull request end to end, covered by an automated end-to-end test on all three platforms |
| **M2 — The ladder** | Brewer and recipe files (JSONC + JSON frontmatter), routing by label, with the Innkeeper's suggestion through `foedrum mash`, decomposition into single-repository sub-orders, bottling, `code` and `release` dependencies (GitHub release or tag), session step `/foedrum:refine`, decomposition approval, Conditioning lane, rewind, review/fix loops with tasting lenses and the Brett mutation check, slash commands, budgets, house yeast (three layers, candidates, scoped selection within a budget, suppressions) | An order across two repositories, where the second needs a release of the first, ends with two linked pull requests and the version bump; routing is visible and overridable |
| **M3 — Open doors** | README with banner, documentation, release pipeline (package smoke test on three platforms, provenance, trusted publishing), contribution guide and CLA with its check, trademark policy, repository made public | The repository is open to read and to contributors: `CONTRIBUTING.md`, `CLA.md` with the CI check, `TRADEMARK.md` and the README are merged |
| **M4 — Blind tasting** | Tasting room repository, Flight runner, reports, model watcher opening upgrade pull requests, house yeast promotion to checks and curation | An automatically generated model-upgrade pull request with an evaluation report |
| **M5 — Strong ales** | Half-pint, Pint, Growler and Keg at scale, Guest tasting, Infection check (triage of target-repository issues), Re-pitch, managed clones, package-registry release signals (NuGet, npm), pre-release development, GitHub App authentication, packs | Target-repository bug reports become Brewery orders with confirmed root causes |
| **M6 — Brewhouse** | Session steps `triage` and `review`, cross-machine `resume` (after a spike), the Innkeeper's planning session, automatic recipe choice (#373), the Maltster shaping requests into issues, the Tapster showing finished work, the board and the tab, local dashboard (Server-Sent Events) with live session output and pending questions answered in place, tasting log, diagnostics, verification in real environments, visual recipe editor | A live board of all batches; a recipe edited visually and saved as a pull request |
| **M7 — Public launch** | Upgrades for existing Breweries (a version, upgrade notes, `doctor`), demo recording, a confidence period of real use, the first npm publish | Real issues brewed in a test Brewery over two weeks each end in a merged pull request or a clean stop with its reason, none hangs or loses work; then `npx foedrum init` works on Windows, macOS and Linux from the published package |
| **Later — More trackers** | `Tracker` and `CodeHost` adapters beyond GitHub (Jira, Linear, GitLab) | An order from a non-GitHub tracker produces a pull request |
