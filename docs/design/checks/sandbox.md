# The check sandbox

A check's command line runs in an OS sandbox of Foedrum's own (`sandboxedChecks`, `src/platform/check-sandbox.ts`): `bwrap` on Linux and WSL2, `sandbox-exec` on macOS, with no network, the home folder hidden, and writes only in the worktree and a temporary folder; where that sandbox cannot start, the check is unstarted, never run without it.
On native Windows it runs as before, each reading says `unsandboxed`, and `foedrum serve` says so at start; a Brewery that requires the sandboxed level does not start there with a check step ([ADR 0076](../../adr/0076-check-steps-run-in-an-os-sandbox-with-no-network.md)).
The worktree's repository is bound read-only, and with it each object store that repository's `objects/info/alternates` names, only when it names one and the repository lies outside the worktree, where a check could plant one (`borrowedStores`): for the checks on an open pull request's merged tree, a worktree of Foedrum's own git directory that borrows the clone's objects, the same objects a check step's worktree already reads with the clone's repository, named only by the alternates file Foedrum writes in a directory no check or brewer writes ([ADR 0203](../../adr/0203-an-open-pull-request-s-checks-run-on-its-merged-tree-when-its-base-moves.md)).
