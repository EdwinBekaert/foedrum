# Check steps

A **check step** (a gravity reading) is an attempt like a brewer's, with a worktree of its own at the task tree, that `stepRunner` (`src/engine/step-runner.ts`) starts on the check runner (`src/checks/check-runner.ts`) instead of claude: it runs each check's command line from `foedrum.jsonc` (its platform override, else `run`), or a Brewery's literal `{ "run": … }`, through the platform shell and the process runner, in order, until the first that does not pass, with the step's deadline (its own, else 30 minutes) as the timeout and the brewers' minimal environment (`buildBrewerEnv`, no GitHub token, none of claude's credentials).
A `null` check is skipped.
`step.finished` records a reading per check, with the exit code, or the signal that ended it, and the last 4,000 characters of the output, each line that looks like a secret left out (`findSecrets`, `src/formats/secrets.ts`); a check ended by a signal fails as an exit code does; a failed check fails the step without a retry and follows its `onFail` route, whose rounds are counted from the `route` its attempts record, else the batch is Stuck; a check that wrote too much or could not start blocks it on its environment; an attempt that read nothing is tried again, at most 3 times.
Once its `test` check exited 0, a step in a repository with a [test map](test-map.md) reads the map at the base and at its tip ([ADR 0280](../../adr/0280-a-new-module-is-judged-unreached-only-on-a-passing-test-run.md)): a module only the batch's map adds that wrote no report, a report path that is refused, or a base map that cannot be read, makes the batch Stuck on its environment, and a batch's map that cannot be read fails the step without a retry, along its `onFail` route.
Before its setup and its checks, a step that runs the tests (a red proof, or a step with a `test` check) reads the freshness of the map at its tip ([the test map](test-map.md), [ADR 0282](../../adr/0282-a-stale-test-map-sends-back-the-change-that-made-it-and-the-maltster-surveys-a-new-one.md)): a map in the repository that the batch's change left stale fails the step without a retry, along its `onFail` route, a git read that fails blocks it on its environment, and any other stale map is recorded on `step.finished` as `staleMap` and named in the status comment.

A check step's deadline is its own or 30 minutes; it has no stall limit, and it is tried again only after an attempt that read nothing, at most 3 times.
The recipe's last check that expects to pass, when an openPullRequest step follows it (Nip's `green`), first gets the base merged into its worktree by the driver, before its setup and its checks; a conflict blocks it on a divergence before any reading ([ADR 0164](../../adr/0164-a-batch-merges-its-base-before-its-last-check.md), [the openPullRequest action](../recipes/open-pull-request.md)).
Before its checks, once nothing else blocks the step, it runs the repository's `setup` in that worktree, within its own `timeout`; its reading comes first, and a setup that does not pass makes the batch Stuck on its environment, not along `onFail` ([ADR 0140](../../adr/0140-a-repository-s-setup-runs-before-a-check-step-s-checks-with-the-network.md)).
The setup runs in the checks' sandbox with the network kept, the home folder and its package caches hidden, so each setup downloads what it installs ([ADR 0158](../../adr/0158-a-repository-s-setup-runs-in-the-check-sandbox-with-the-network-kept.md)).
The same setup also runs before the attempt of every brewer with a shell, so check steps never reuse a brewer's install: each worktree installs its own ([ADR 0163](../../adr/0163-a-repository-s-setup-runs-before-a-brewer-attempt.md)).
