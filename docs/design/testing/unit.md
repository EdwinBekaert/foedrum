# Unit tests

**Unit tests** (`node:test`) for the fold, state machine, recipe parsing, GitHub client (an injected process runner standing in for `gh`).
They start no processes: git, npm and other tools are reached through an injected process runner, and `npm run check` stays under 20 s ([ADR 0021](../../adr/0021-unit-tests-spawn-no-processes.md)).
The check fails when a file under `test/unit/`, `test/property/`, `test/chaos/` or `test/helpers/` imports `node:child_process` or the process runner, and when one unit test file uses more than 5 s of CPU time (property and chaos files, whose run count sets their time, more than 15 s).
The budget is CPU time, which each test process reports itself, so queueing behind a parallel check or other sessions does not count ([ADR 0036](../../adr/0036-test-budget-in-cpu-time.md)); since the same work still takes more CPU time on a loaded machine, a file over it in the run is run again alone, up to three times, and the lowest reading counts ([ADR 0089](../../adr/0089-a-file-over-the-test-budget-is-measured-again-alone.md)); that fails only in CI, and outside it a file over its limit is listed in the report and fails nothing, since other sessions' load can outlast every run alone ([ADR 0136](../../adr/0136-the-test-budget-fails-only-in-ci.md)); it catches costly files, not a file that only waits, which is left to the 20 s goal, the wall time the check lists beside the CPU time, and review.
A process started through an imported module fails the test instead: `npm test`'s preload makes `node:child_process`'s process starts throw in the test processes and fails the file that made one ([ADR 0038](../../adr/0038-npm-test-processes-refuse-process-starts.md)).
`npm run check`, and so the push gate, runs only the test files the change reaches: those whose relative imports lead to a file changed since the merge base with `origin/main`, untracked files included, without coverage ([ADR 0241](../../adr/0241-each-test-runs-at-the-stage-where-it-pays-the-check-runs-the-test-files-a-change-reaches.md)).
A change to the package files, `tsconfig.json`, `scripts/`, `test/helpers/`, `test/fixtures/` or any other file that is not TypeScript outside the docs runs every test file; a change only to the docs runs none.
CI runs `npm run check -- --all` on every leg: every test file with coverage and its thresholds, the full gate a merge waits for.
CI reports how long the check took.
