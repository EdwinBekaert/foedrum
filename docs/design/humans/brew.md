# foedrum brew and the plugin

- **Interactive:** an engineer opens Claude Code and types a plugin command, for example `/foedrum:brew 21`.
  The session drives the batch, without `foedrum serve` running: `/foedrum:brew` runs `foedrum brew --via plugin` in the background, shows where the batch went when it exits, and on `needs_input` asks the engineer each question, runs `foedrum answer` and brews again ([ADR 0125](../../adr/0125-the-foedrum-plugin-is-markdown-skills-that-run-the-terminal-with-via-plugin.md)).
  Judgement-heavy steps (refine, triage, review) run in the session itself.
  Under it is `foedrum brew <issue> [--as <name>]` ([ADR 0123](../../adr/0123-foedrum-brew-drives-one-batch-under-an-owner-of-its-own.md)): a driver of its own, `--as` or `session-<id>` from `CLAUDE_CODE_SESSION_ID`, on the Cellar's wiring (`wireDriver`, `src/cli/driver-wiring.ts`) with `takes` that one batch; it orders and routes by label an issue with no batch, ticks until the batch is on tap (exit 0), Stuck (3), needs input (4, with the numbered questions `foedrum answer` takes) or cancelled (6), and refuses (5) a batch another driver holds, naming it, unless `--take` takes it over ([ADR 0124](../../adr/0124-foedrum-takeover-hands-a-batch-to-another-driver-as-a-recorded-command.md)), after recording the end of the run it stopped, within a lease, when a takeover that resumes a step took the batch ([ADR 0127](../../adr/0127-foedrum-resume-takes-a-running-batch-over-and-continues-its-step-s-session.md)); a Stuck batch keeps its lease while the engineer answers.
  It prints its status comment's link once the comment is made (a claimed issue's on its Brewery issue), and about every 30 s while its lane line stays the same which attempts run and for how long ([ADR 0154](../../adr/0154-lane-labels-on-the-order-s-issue-and-the-status-comment-s-path-line.md)).
  On a terminal (standard output a TTY, `TERM` not `dumb`, `CI` not set) it prints those 30-s lines no more and keeps one live line instead, redrawn about once a second, also while a takeover waits for the runs it stopped: an ASCII spinner, then per running attempt its step and attempt, elapsed time, turn, last main-thread tool call as its name and one safe word (a path inside the worktree, `outside`, `(left out)`, or a shell command's prefix), and `denied` after a denial, or `setup` while the repository's setup runs; ASCII only, every other code point escaped, cut to the terminal's width less one; a lasting line clears it, prints and draws it again, and it is cleared before any exit ([ADR 0174](../../adr/0174-foedrum-brew-keeps-a-live-line-on-a-terminal.md)).
