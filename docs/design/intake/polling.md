# Polling

- **Polling intake** with conditional requests: works on a laptop with zero infrastructure ([ADR 0008](../../adr/0008-polling-intake.md)).
  ADR 0052 sets the polling interval at a minute, which `foedrum serve` applies (`pollEvery`, ADR 0068); every GET through the cached reads carries the ETag of the answer before (a failed Actions job's log, read once, does not, [ADR 0228](../../adr/0228-a-failed-actions-job-s-log-goes-with-the-batch-back-to-its-fix-step.md)), so an unchanged poll is a 304 that costs no rate limit, and a list is read along its `Link` pages, and on past a full page that answers 304, which has no such header ([ADR 0333](../../adr/0333-a-brewer-s-order-holds-the-maintainers-comments.md)), 10 items a page, so the longest bodies anyone can write never pass the answer limit.
  A pass lists the Brewery's issues when there is free capacity or an Ordered batch waits for it, and an intake repository's only when there is free capacity to claim in it, before it orders anything ([ADR 0156](../../adr/0156-a-claimed-order-is-routed-by-its-brewery-issue-s-recipe-label.md)); what it orders, ready sub-orders included, and in what order is [ranking](ranking.md)'s.
  A target repository's listing asks GitHub for its filter's labels, and the cache keeps at most 64 MiB of answers, one list at most 32 MiB ([ADR 0068](../../adr/0068-the-intake-in-foedrum-serve-brewery-orders-and-routing-by-label.md)).
  A GET that timed out is tried once more, unless its caller gave it up or a pause began; a write is not, and a dead network costs a read 60 s instead of 30 s ([ADR 0336](../../adr/0336-small-rough-edges-of-the-self-brew-trial.md)).
  On a rate limit the GitHub client pauses as GitHub's answer says and fails every request until then, never waiting inside a call, so no intake pass or effect overruns its deadline (`createGitHubReads`, `src/github/reads.ts`; `githubTargetTracker`, `githubIssueMarks`; [ADR 0052](../../adr/0052-github-reads-rate-limit-pauses-and-the-polling-interval.md)).
