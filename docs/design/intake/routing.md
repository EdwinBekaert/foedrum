# Routing

- **Routing:** a `recipe:<name>` label wins, and `foedrum serve` chooses no recipe for an unlabelled issue by itself; `foedrum brew` on one routes it to the Brewery's default recipe, a router's choice ([ADR 0370](../../adr/0370-foedrum-brew-runs-the-brewery-s-default-recipe-on-an-issue-with-no-recipe-label.md)); `foedrum mash` has the Innkeeper suggest a recipe and a person choose it ([ADR 0232](../../adr/0232-foedrum-mash-routes-an-issue-to-the-innkeeper-whose-question-the-answer-chooses-the-recipe-by.md)), and `foedrum mash --override` asks again for an issue that has one ([ADR 0374](../../adr/0374-foedrum-mash-override-asks-the-innkeeper-again-for-an-issue-with-a-recipe.md)), and `foedrum recipe` changes it on a batch that is not brewing ([ADR 0240](../../adr/0240-order-and-recipe-work-by-the-brewery-issue-on-both-surfaces.md)).
  In M1 the intake orders a Brewery issue only when an allow-listed user opened it with a `recipe:<name>` label and it is not labelled `foedrum:sub-order` ([ADR 0285](../../adr/0285-an-approved-plan-becomes-brewery-sub-issues-through-the-ledger.md)), and each pass routes every Ordered batch whose issue it read by its one such label, whoever ordered it (this pass, a pass killed before it routed, a retry from Stuck on routing).
  Two labels or a recipe the Brewery lacks is reported once; no label waits for the routing deadline, then Stuck on routing.
  A batch whose recipe brews its `concurrency` waits Ordered, is reported once and keeps its routing deadline ([limits](limits.md)).
  Labels count only while a batch is Ordered: a relabel after routing changes nothing ([ADR 0068](../../adr/0068-the-intake-in-foedrum-serve-brewery-orders-and-routing-by-label.md)).
  `foedrum mash <issue>` routes a Brewery issue's Ordered or routing-Stuck batch, a claimed order's included, to `mash-in`, whose Innkeeper asks which recipe brews it; the answer chooses the recipe, restarts the batch on it and labels the issue `recipe:<name>` once, through the ledger, for its next order ([ADR 0232](../../adr/0232-foedrum-mash-routes-an-issue-to-the-innkeeper-whose-question-the-answer-chooses-the-recipe-by.md)).
  An issue with no batch yet is ordered first, as `foedrum brew` orders it; a batch that already started a recipe is refused with a line that names `foedrum recipe`, and one on tap or cancelled with `foedrum order`'s refusal, as `brew` refuses it ([ADR 0339](../../adr/0339-an-issue-has-one-live-batch-no-second-batch-while-its-pull-request-is-open.md)).
  The question names the Brewery issue's number, which the Innkeeper reads from the `source` of its `order` input, `issue #864 body, the order on Brewery issue #19` for a claimed order ([ADR 0334](../../adr/0334-every-line-names-the-number-and-the-innkeeper-reads-it-from-its-input-s-source.md)).
  Nothing is mashed by itself: under `foedrum serve` an unlabelled issue still waits for the routing deadline.
  `foedrum brew <n>` on an issue with no recipe label, an Ordered batch or a claimed order's Brewery issue included, routes the batch to the Brewery's default recipe, `foedrum.jsonc`'s `defaultRecipe` (a recipe of type `mash`) or else `mash-in`, so it ends at the Innkeeper's question, where it refused ([ADR 0370](../../adr/0370-foedrum-brew-runs-the-brewery-s-default-recipe-on-an-issue-with-no-recipe-label.md)).
  The route is the router's, `source: "router"`, which labels nothing; the answer labels the issue as above.
  A brew of a claimed issue routes the Brewery issue it opens to the default after the tick that opens it.
  Two labels or a recipe the Brewery lacks are refused as before, and a Brewery whose default cannot run (no recipe of its name, a left-out default whose `mash-in` the Brewery replaced with one that builds, or fewer than two recipes for its question) says so in one line before anything is ordered.
  The model call is the person's, who asked about that issue; `serve` would make one for every unlabelled issue anyone opened, which ADR 0232 rejected.
  A claimed batch is routed by its Brewery issue's label, never its target issue's ([target issues](target-issues.md), [ADR 0156](../../adr/0156-a-claimed-order-is-routed-by-its-brewery-issue-s-recipe-label.md)).
