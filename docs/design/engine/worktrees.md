# Worktrees

- **Always worktrees, never a clone per batch** ([ADR 0012](../../adr/0012-worktrees-from-local-clones.md)).
  Per repository, `source` is `local` (default: worktrees from the user's existing clone, in Foedrum's own branch namespace `foedrum/…`, never touching the checked-out branch) or `managed` (one bare partial clone per repository, created once, optionally borrowing objects from a local clone).
  Worktrees live in a **work root outside the Brewery checkout** (default `~/.foedrum/<owner>.<name>/`, set per machine in `.foedrum/local.jsonc`; short on Windows), so a brewer only ever sees the target repository's own instruction files — never anything placed in the Brewery.
  A repository's `source` and `base` (the branch a batch starts from, at `origin/<base>`, default `main`; later attempts continue from its task tree, [ADR 0066](../../adr/0066-the-task-tree-continues-from-the-latest-succeeded-attempt.md)) are in `foedrum.jsonc`; the path of the user's clone of a `local` repository is in `.foedrum/local.jsonc`, since it differs per machine ([ADR 0063](../../adr/0063-foedrum-serve-its-configuration-and-wiring.md)).
- **Attempt worktrees** ([ADR 0029](../../adr/0029-attempt-worktrees-layout-claims-and-repair.md)) live at `<workRoot>/<owner>.<name>/attempts/<batchId>/<stepId>/<attempt>` on the branch `foedrum/<batchId>/<stepId>/<attempt>`; a managed clone is `<workRoot>/<owner>.<name>/clone.git`.
  One cleanup, at engine start (crash repair) and when a batch ends, removes what the state no longer claims: everything in the attempts root of an ended or unknown batch, and the local branches of an ended one.
  A Stuck batch, a worktree with a live lease, and a worktree with changes are kept, except that its step's own untracked out doc, alone, does not count: it is deleted and the worktree goes ([ADR 0081](../../adr/0081-the-cleanup-ignores-the-steps-own-out-doc.md)); branches of a batch the state does not know stay and are reported, also when its clean worktree goes, since they may hold the only copy of unpushed work and another Brewery may share the clone.
  So does the branch of an ended batch's task tree that no push recorded, or for a rewound task tree the attempt branches that may hold the rewind's commit ([ADR 0101](../../adr/0101-the-cleanup-keeps-the-attempt-branches-that-hold-a-rewound-task-tree.md)), while it holds commits past the batch's start (`Claims.unpushed`, [ADR 0084](../../adr/0084-a-batch-s-commits-end-in-a-pull-request-or-on-a-kept-branch.md)); `foedrum status` lists each such branch with its batch, its commits past the start and the line that drops it, read through the engine's git in the clone ([ADR 0092](../../adr/0092-foedrum-status-lists-the-task-tree-branches-the-cleanup-keeps.md)).
  The branch of the task tree of a batch On tap whose pull request is open is kept too, so a fix round its pull request's failure sends it into has a tree to start from (`Claims.open`, [ADR 0219](../../adr/0219-a-failing-check-on-an-open-pull-request-sends-its-batch-back-to-a-fix-step.md)); it goes once the pull request ended, at the batch's next cleanup or the next repair.
  A retry or an answered attempt that resumes a session (`retryMode: resume`) runs in the worktree of the attempt whose session it continues, once that attempt's process is gone, covered by its own lease, which claims every attempt of the sessions it continues, back through `session.resumes`, and of a session that kept its id when resumed, later attempts too, since a lease covers its session (`worktreeClaims`, `src/engine/worktree-claims.ts`); otherwise it starts fresh in a worktree of its own.
  Only a retry or an answered attempt resumes (`step.scheduled`'s `retry` or `answered`), once the attempt before it finished with claude's init report: the driver recreates the worktree of the attempt that started the session and records `session.resumes` with no `worktree` of its own, the plan runs `--resume` with a short prompt to go on, after an answer with that round's answers as its one input, and a resumed success hands the task tree on as the branch of that worktree; a routed attempt, a retry after a success, a lost or abandoned one, one without the report, or one whose worktree cannot be recreated starts fresh and records why (`session.fallback`), and a resume that finds no session fails retryably, so its retry starts fresh (`resumeOf`, `src/engine/session-resume.ts`; the driver's `resumes`, which `serve` and `brew` set from the brewer's `retryMode`, and for the retry of a turn overrun always, which fails instead of starting fresh unless the run before found no session, [ADR 0175](../../adr/0175-a-turn-overrun-is-retried-by-resuming-its-session-and-keeps-its-out-doc.md); [ADR 0117](../../adr/0117-a-retry-resumes-the-session-of-the-attempt-before-it-in-that-attempt-s-worktree.md), [ADR 0118](../../adr/0118-retrymode-resume-loads-and-an-answer-resumes-the-session-that-asked.md)).
  The red proof and the testsUnchanged guard read the worktree and branch a resumed attempt ran in (`ranIn`).
  Removal uses `removeTree`, records are pruned one by one (never `git worktree prune` in the user's clone), kept worktrees no attempt runs in lose a stale `index.lock`, and git never runs by discovery inside an attempt worktree: its state is read against its record, and that status, which looks into no submodule, and `git worktree remove` run with `core.fsmonitor` off and no hooks, so a brewer that rewrites its `.git` file cannot make the engine run a command ([ADR 0095](../../adr/0095-the-cleanups-read-a-worktree-through-its-record-and-run-no-fsmonitor-or-hook.md)).
  A pure core (`src/workspace/attempt-worktrees.ts`) decides, the shell (`attempt-worktrees-git.ts`) runs git: before a new attempt it fetches in the clone, by its `origin`, with `--prune` (a branch the remote made again as a folder never stops it) and no auto maintenance or submodules, one fetch at a time, and every git call it makes in the clone runs with no hook or fsmonitor of the clone's ([ADR 0137](../../adr/0137-the-push-its-lookup-and-the-worktree-fetch-run-in-the-clone-again.md)).
  An attempt writes in its batch's repository: a claimed issue's, a sub-order's, or the Brewery's only one for a Brewery order; an order that names none among several fails its attempts retryably until it is Stuck (`repositoryOf`, `src/engine/driver.ts`, ADR 0063).
  A driver makes an attempt's worktree under the attempt's lease and records it in `step.started` (`worktree: { repo, path, branch, commit }`); an attempt whose worktree cannot be made fails retryably.
  A new attempt's worktree starts at the batch's **task tree**: the branch its latest attempt that succeeded committed on (its own worktree's, or for a resumed attempt that of the worktree it ran in, ADR 0117), or its latest rewind's commit, whichever came last, else the base (`Batch.taskTree` in the fold, `taskTreeStart`, `src/engine/task-tree.ts`).
  So a step sees the earlier steps' commits, a fresh retry starts where the failed attempt started, and attempts still never share a worktree at the same time (a resumed attempt takes over the worktree of the session it continues, [ADR 0029](../../adr/0029-attempt-worktrees-layout-claims-and-repair.md)); check steps and the push find the task tree the same way ([ADR 0066](../../adr/0066-the-task-tree-continues-from-the-latest-succeeded-attempt.md)).
  It cleans a batch's worktrees, and its attempt settings files under `<workRoot>/attempt-settings/<batch>/`, when the batch ends, again when an attempt of the ended batch lets its lease go, and again once no lease of a batch whose cleanup kept a worktree under one is alive, also when that lease expired because its run never ended ([ADR 0061](../../adr/0061-chaos-faults-at-sites-shrinking-worktrees-and-the-state-branch.md)), and repairs every batch at its start (`createWorktreeCleanup`, `src/engine/worktree-cleanup.ts`; `startDriver`, `src/engine/driver-start.ts`; [ADR 0037](../../adr/0037-attempt-worktrees-in-the-engine-and-driver-locks.md)).
