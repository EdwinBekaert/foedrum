# M1 — First pour

Open · [GitHub milestone](https://github.com/EdwinBekaert/foedrum/milestone/2)

M1 takes a real issue in a test Brewery to a pull request, end to end. This page gets the rest of
what M1 built when the milestone closes; until then it shows how to see the Cellar at work.

## See it

```sh
npm ci
npm run demo
```

`npm run demo` makes a scratch Brewery and target repository in `.foedrum/tmp/demo/`, with bare
remotes there, and brews one order through `foedrum serve`'s own Cellar. The brewer is scripted
and the code host is an in-process fake, so it needs node and git only: no gh, no GitHub, no
`claude`, no network, and nothing on your machine's git configuration (ADR 0097). It takes about
half a minute.

It walks through seven steps and waits for Enter between them. `npm run demo -- --no-pause` goes
straight through, as it does when its input is not a terminal.

| Step | What to look for |
|---|---|
| 1. The diagnosis serve runs with | The demo's own diagnosis, not `foedrum doctor` on your machine: the demo starts no `claude` and no gh, so it checks neither. |
| 2. The order comes in | An issue in the Brewery, labelled for its recipe by a user it lists, is all serve needs to take it as a batch. |
| 3. `foedrum status` as the batch moves | The batch goes from the order to brewing, and `brew #1` is started when the Cellar is killed. |
| 4. The kill and the restart | The Cellar is killed with SIGKILL mid-attempt. The restart finds `brew #1` lost with it and brews it again as `brew #2`. |
| 5. The pull request and the status comment | One pull request and one status comment on the fake code host, though the Cellar lived twice. The comment is shown as its Markdown, without its hidden revision marker. The pull request is #2 because the fake host numbers comments and pull requests from one counter. |
| 6. On tap | `foedrum status` shows the batch on tap, with its pull request. |
| 7. `foedrum replay 1-1` | Every event the batch went through, and the state the fold makes of them. |

`foedrum status` and `foedrum replay` are the CLI's own commands, run in the scratch Brewery:
they read its event store, and nothing else that could reach GitHub.
