# 0313. The engine runs Brett's mutants in scratch trees against a fresh baseline

Date: 2026-11-03 · Status: Accepted · Amends [0017](0017-test-first-recipes-and-tasting-lenses.md) (what a `scratch` tree is, and who runs the mutants), [0040](0040-brett-covers-scripts-and-kills-need-a-failing-test.md) (the engine's verdict and its deadlines) [0203](0203-an-open-pull-request-s-checks-run-on-its-merged-tree-when-its-base-moves.md) (its checkout is shared with the scratch tree) and [0311](0311-brett-s-mutants-of-a-target-land-on-lines-the-change-added-in-a-code-area-of-the-test-map.md) (the engine now calls `mutantCheck` and runs the mutants)

## Context
[ADR 0017](0017-test-first-recipes-and-tasting-lenses.md) has the engine, not the model, decide which of Brett's mutants count: it applies each in a disposable `scratch` tree and runs the gravity reading, and a mutant the tests still pass is a confirmed survivor.
[ADR 0040](0040-brett-covers-scripts-and-kills-need-a-failing-test.md) says only a test the mutant makes fail kills it, compared test by test with a baseline of the unmutated tree, and that a run that hits its deadline counts as killed.
[ADR 0311](0311-brett-s-mutants-of-a-target-land-on-lines-the-change-added-in-a-code-area-of-the-test-map.md) gave Brett a `mutants` out doc and `mutantCheck`, which nothing called.
The brewer schema names a `scratch` tree, which nothing created.
The check runner runs a repository's `test` check and reads every test's outcome from the test map's reports, with the parsers the red proof uses ([ADR 0274](0274-the-red-proof-reads-line-coverage-of-the-change-and-a-test-map-not-test-names.md), [ADR 0304](0304-a-failed-test-reading-names-its-failing-tests-from-the-test-map-s-reports.md)).
The merged tree of an open pull request is already checked out in a worktree of a git directory of Foedrum's own and removed after its run ([ADR 0203](0203-an-open-pull-request-s-checks-run-on-its-merged-tree-when-its-base-moves.md)).

## Decision
- **The work happens inside the Brett step, after its session ends.** `mutated` in `src/checks/mutant-run.ts` wraps the brewer runner outermost in the driver wiring, beside the survey and the testsUnchanged guard. It acts on an attempt whose brewer writes the `mutants` out doc, found in the recipe the attempt was scheduled under ([ADR 0310](0310-the-driver-wiring-finds-an-attempt-s-brewer-in-the-recipe-it-was-scheduled-under.md)), once its session succeeded with a worktree. An attempt that failed, asked, or ran in a Brewery order's checkouts runs no mutant.
- **Each mutant is checked against the batch's change first.** The change is read in the clone from where the batch started (its merged base, else its start, [ADR 0164](0164-a-batch-merges-its-base-before-its-last-check.md)) to the attempt's commit. The effective test map's code areas and the diff's added lines give `mutantCheck` its `TargetChange`, and git reads each named file at the commit. An invalid mutant is recorded with its reason and never runs. If no mutant is valid, nothing runs, not even the baseline.
- **One fresh scratch tree per run.** `openCommitTree` in `src/workspace/merge-tree-git.ts` checks the attempt's commit out in a worktree of a git directory of Foedrum's own, borrowing the clone's objects and holding a copy of its tags and remote-tracking refs, as the merged tree does (the checkout is now one helper both use). It applies a mutant's line edit to the file as git checked it out, so the file keeps the line endings and encoding the baseline's tree has (Git for Windows checks text out with CRLF), but only when that file is a regular file inside the tree and reads as UTF-8 without loss (a lossy decode would change its other bytes, so its mutant is not judged), so a link the change committed cannot lead the write elsewhere. It removes the tree and the directory when the run ends, also when it fails. The baseline gets one tree, and each valid mutant a fresh one. Reusing one tree and restoring the file between runs would keep what a run wrote (reports, caches, build output), and the baseline holds only against a tree no run has touched.
- **Each run is the repository's whole `test` check, its setup first.** `testRun`, beside `checkTree` in the check runner, clears the report paths of the effective map's modules, runs the setup (a fresh tree has no dependencies) and the `test` check, and reads each module's reports where the map says, a TRX report left unread. Test selection stays separate ([ADR 0274](0274-the-red-proof-reads-line-coverage-of-the-change-and-a-test-map-not-test-names.md)). The runs go one at a time, at normal priority for now: running them below normal priority is #809.
- **The verdict, as ADR 0040, from every test's outcome.** `judgeRun` in `src/checks/mutant-verdict.ts` compares the leaf tests of the module whose code area holds the mutant's file, by name, counting how often each name passed and failed. A report's location may be an absolute path, which differs between scratch trees, so it takes no part. A test of the run that fails more often or passes less often than at the baseline, or a test that passed at the baseline and no longer reports, kills the mutant, and the first such test is named. A test that fails in both runs kills nothing. No passing test of the module at the baseline, or no report from the module in the run, is `notJudged`. A run with no report whose test check failed is a mutant that broke the build, and its reason says so (`the mutant broke the build: module "x" wrote no test report and its test check failed`). It counts as neither killed nor survived, since no test ran against it, as [Stryker](https://stryker-mutator.io/docs/mutation-testing-elements/mutant-states-and-metrics/) records a CompileError and PIT a non-viable mutant. Brett's prompt already asks for no mutant that only breaks the build. A run whose test check ends other than by exiting (killed, signalled, unstarted), or whose tree or reports fail, is `notJudged` with why.
- **Deadlines.** Every run ends a minute before the step's deadline, so the attempt ends in time. While the wrapper judges, it reports the attempt's progress as live, so its lease holds and no test run reads as a stalled brewer ([ADR 0027](0027-supervisor-lost-and-stalled-attempts.md)): the runs' own deadlines bound it. A mutant's run gets three times the baseline's wall time, at least a minute, and no more than that minute before the step's deadline. A run that hits its own deadline is `timedOut`, which counts as killed. One cut off by the step's margin is `notJudged`, and so is every mutant left when the margin comes. The attempt succeeds whatever the verdicts. Blocking on survivors is #799.
- **The record.** `step.finished` gains `mutants`: at most five entries, each the file, the line, Brett's description and the verdict (`killed` with the test, `survived`, `timedOut`, `invalid` with the reason, `notJudged` with why). Every text is put on one line, cut, and left out when it looks like a secret, as a failing test's name is, so a reason names a test map by where it was read, never by a commit hash, which reads as one ([ADR 0304](0304-a-failed-test-reading-names-its-failing-tests-from-the-test-map-s-reports.md)). A store from before reads as today. The fold keeps them on the attempt, and `foedrum replay` lists them under the batch's state.

## Consequences
- A Brewery recipe with a `brett` step records each mutant's verdict on the attempt. No default recipe runs Brett, so nothing changes on a default recipe.
- A Brett attempt takes as long as `1 + n` test runs of the repository, each with its setup, for `n` valid mutants (at most five), within Brett's 20-minute deadline. A slow suite leaves later mutants `notJudged`.
- A flaky test can still kill a mutant at random, as in Foedrum's own reviews. The fresh baseline makes that rarer.
- Two tests of one module with the same name are counted together: a mutant that fails one of them still kills, by that name.
- The runs start at normal priority until #809.

## Alternatives considered
- **Run the mutants in the attempt's own worktree.** Brett is read-only, and its worktree is the driver's to clean. A test run there would also leave its reports for the next attempt.
- **One tree, `git checkout -- <file>` between mutants.** Faster, but a run's own writes stay, and a baseline taken there no longer stands for the commit.
- **Run only the test files that cover the mutant's line, as Foedrum's own review does ([ADR 0303](0303-brett-s-mutants-run-only-the-test-files-that-cover-their-line.md)).** That needs a per-file coverage map in every language, which a target's test map does not give. Selection stays separate (ADR 0274).
- **A failed attempt when the deadline comes first.** The mutants are advisory, and an attempt that ran out of time to judge them did its own work. `notJudged` says what was left.
