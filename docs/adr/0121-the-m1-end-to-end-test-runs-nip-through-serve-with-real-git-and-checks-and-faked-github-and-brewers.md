# 0121. The M1 end-to-end test runs Nip through serve, with real git and checks, and GitHub and the brewers faked

Date: 2026-10-22 · Status: Accepted

## Context
M1's exit criterion (ROADMAP, #180) is that a real issue in a test Brewery becomes a pull request end to end, covered by an automated end-to-end test on all three platforms. The default recipe is Nip (`defaults/recipes/nip.jsonc`): the Gauger commits failing tests, a red proof reads them red, the Cellarman makes them pass under the testsUnchanged guard ([ADR 0078](0078-the-red-proof-reads-the-test-report-and-testsunchanged-compares-lines.md)), a check step reads the result and sends a failure back to the Cellarman with its reading ([ADR 0128](0128-an-attempt-a-route-schedules-gets-what-sent-it-back.md)), and openPullRequest pushes the bottle branch and opens the pull request ([ADR 0071](0071-the-openpullrequest-action-two-effects-of-the-batch.md)).

`npm run demo` ([ADR 0097](0097-npm-run-demo-is-a-script-on-serve-s-seams-with-the-tests-fakes.md)) already drives serve end to end, but on a one-brewer recipe with `testFirst: false`, so the red proof, the guard, a real check step and the route input are not in its path. Three things needed deciding: what such a test runs for real and what it fakes, where it runs, and how the real `claude` takes part.

Two constraints decide most of it. Foedrum never holds a GitHub token, and reaches GitHub only through gh's own login ([ADR 0073](0073-github-only-through-gh-s-own-login.md)), so there is no test organisation, account or token for CI to use; and no test of any layer reaches a login or a remote service, nor any test runs a model in CI ([ADR 0057](0057-real-claude-tests-are-opt-in-and-claude-proofs-leave-the-suite.md)).

## Decision
- **One integration test, `test/integration/nip.test.ts`, in `npm run test:integration`,** so CI runs it on every leg (Windows, macOS, Linux). It runs serve's own `runServe` with `serveShell`'s machine ([ADR 0063](0063-foedrum-serve-its-configuration-and-wiring.md)) in the test's process, on a throwaway Brewery and target repository in the checkout's `.foedrum/tmp/tests/`, each a clone of a local bare remote, until the batch is on tap with its status comment, or Stuck (`lifeEndOf`, ADR 0097).
- **Real:** git, the attempt worktrees and their fetches, serve's shell (lock, store, state branch, intake, the driver's wiring), the recipe loader with Nip, the Gauger and the Cellarman from `defaults/` ([ADR 0098](0098-foedrum-s-defaults-load-under-the-brewery-s-files-and-a-brewer-input-can-name-a-lens.md)), the attempt plans and prompts, the check runner running the target's own `node --test` ([ADR 0069](0069-check-steps-run-the-repositorys-commands-in-an-attempt-of-their-own.md)), the red proof ([ADR 0064](0064-test-first-recipes-when-onblocked-and-a-red-proof-required.md)), the testsUnchanged guard, the route input, the push of the bottle branch with its secret scan, and the ledger. Every git reads a configuration of the test's own (the demo's `gitConfig`): an identity, no signing, and the target's GitHub URL sent to its bare remote, every other GitHub URL to a path that does not exist ([ADR 0096](0096-the-engine-s-git-reaches-the-remote-outside-the-clone-s-configuration.md)).
- **Faked, at serve's own seams:** GitHub is the tests' fake GitHub API behind the tests' fake gh (`gh`), in process, holding the Brewery's one issue labelled `recipe:nip`; the brewers are the scripted Gauger and Cellarman (`runner`) of the Nip fixture; and `wait` ends the run. The diagnosis is the demo's: no `claude` to start, no sandbox.
- **The Nip fixture, `test/helpers/nip-fixture.ts`,** holds the target repository (`greet.mjs` and one `node --test` test), the Brewery's files (no recipe or brewer of its own, so Nip comes from `defaults/`), the order, and `scriptedNip`. Each scripted attempt asks serve for its plan, keeps the prompt, writes its files and its out doc in the attempt's worktree, commits there, and then ends through the tests' `fakeBrewerRunner`, so `settleAttempt` judges it as a real attempt. The Gauger adds a failing test; the Cellarman's first fix fails the test check; its second attempt, scheduled by the route from `green`, passes. `npm run demo` takes the fixture over for #366; it is not a second fixture.
- **The test asserts outcomes, lanes and effects,** never the fields of `step.started`: the steps' outcomes in order (`gauge`, `red`, `implement`, a failed `green`, `implement#2`, `green#2`, `open-pull-request`), the one route from `green` to `implement`, the batch on tap with the one pull request's URL, one `pull_request` effect, a status comment's revision applied, exactly one pull request and one status comment on the fake host, the Gauger's and both of the Cellarman's commits on the bottle branch of the bare remote, and that the Cellarman's second prompt, and not its first, holds the route input with the failed reading.
- **The opt-in real-claude case,** in the same file, behind `FOEDRUM_REAL_CLAUDE=1` (ADR 0057), never in CI: the same run with serve's own claude runner and the real `claude` against the fake Messages API (`test/integration/fake-messages-api.ts`), which now picks its tool calls from each call's body, so one fake plays the Gauger and both Cellarman sessions, each in a session of its own. The diagnosis is doctor's on the machine (the real `claude`, the isolation level the platform reaches), with gh answered from captured output and its login not asked for, since the fake code host is GitHub here. The Gauger first asks for `git push`, which no allow rule matches: the test checks that the probe's own tool result came back as an error and that no ref reached the remote, on whichever level the machine reaches, the sandboxed one on macOS, Linux and WSL2 included ([ADR 0087](0087-sandboxed-commands-go-through-the-allow-rules-and-never-see-credentials.md)). It tests Foedrum's wiring, not whether `claude` works.

## Consequences
- M1's exit criterion is a test CI runs on every pull request on three platforms, with no login, token, network or model. A change to serve's shell, the Nip recipe or its brewers, the checks, the route input or openPullRequest that breaks this path fails it. The test covers the path where the red proof reads red and the testsUnchanged guard lets the Cellarman's commits through; a red proof or guard that passed everything would not fail it, which their own tests cover (`test/integration/test-first.test.ts` , `test/unit/red-proof.test.ts` and `test/unit/tests-guard.test.ts`).
- It takes about 70 to 100 s on a loaded Windows laptop, nearly all of it serve's own git (each attempt makes a worktree and fetches) and the check runs, with the ticks at 100 ms. That is above the minute the issue hoped for; the Linux and macOS legs are faster. The test holds no wall-clock limit (ADR 0070): only the hang guard ends a run that never gets there.
- The check steps run as the checks run at the time: when check steps run in the OS sandbox (#190), this test runs them there with no change of its own.
- What ADR 0087 says of a denied variable (unset before each sandboxed command) is not observed: Nip's brewers are allowed no command that would print their environment. The real-claude case observes only the denied command.
- The fakes in `test/helpers/` gain a third user, and the fake Messages API a second way to be scripted.

## Alternatives considered
- **A test organisation on GitHub with a bot account.** It needs a token in CI, which ADR 0073 rules out, and a remote service in a test, which the test rules rule out; a GitHub outage would fail M1's test.
- **Running the program (`node src/cli/main.ts serve`) as a process,** as the opt-in serve test does. The brewers then cannot be scripted without a seam in the program, and the real gh needs the fake GitHub over a proxy; in process, serve's own `runServe` and `serveShell` run with only three seams replaced, as in the demo.
- **Extending `npm run demo` instead.** The demo is a walkthrough for a person, with a crash in the middle; the exit test should assert one path precisely and stay readable on its own. #366 moves the demo to Nip on this fixture.
- **Scripting the brewers with `behave` alone, without commits.** The red proof, the guard, the checks and openPullRequest read the commits and the worktrees: without real commits there is nothing for them to read.
