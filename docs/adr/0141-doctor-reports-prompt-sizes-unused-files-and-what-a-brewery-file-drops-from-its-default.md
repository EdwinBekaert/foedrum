# 0141. Doctor reports prompt sizes, unused files and what a Brewery file drops from its default

Date: 2026-10-22 · Status: Accepted · Amends [0098](0098-foedrum-s-defaults-load-under-the-brewery-s-files-and-a-brewer-input-can-name-a-lens.md) (doctor says more about the files in use than which defaults they are)

## Context
`foedrum doctor` checks that a Brewery's recipe, brewer and lens files load ([ADR 0053](0053-recipe-files-reach-the-engine-brewer-steps-in-a-line-first.md)) and lists the defaults in use ([ADR 0098](0098-foedrum-s-defaults-load-under-the-brewery-s-files-and-a-brewer-input-can-name-a-lens.md)). Once a team writes its own brewers, three questions come up that a load does not answer (#282): which brewer's prompt is costly, which file nothing uses, and what a Brewery file that replaces a default left out of it. A Brewery file replaces the default of its name whole (ADR 0098), so a copy of the Gauger with one rule deleted loads as well as the original, and nothing says the rule is gone. The answers must stay deterministic and free: doctor makes no model call and reads only the files it already reads.

## Decision
- **Notices, not problems.** Doctor prints the new findings in a `Notices:` block of their own, one line each, after the problems. A notice never changes `ok` or the exit code: doctor still exits 0 on a Brewery whose only findings are notices. The fix side, edits proposed as a pull request, is #284.
- **Each brewer's prompt size.** When the files load, doctor builds every brewer in use's prompt through `assembleBrewerPrompt` (ADR 0041), from its instructions (its file's body) and its `lens:` inputs, in its inputs' order, and prints one line per brewer under `Brewer prompts`: its name, its file, the prompt's size in bytes (UTF-8) and an estimate in tokens, the bytes divided by 4, rounded up. The other inputs (the order, out docs of earlier steps, answers, a route) and the out-doc contract depend on the batch and the repository, so they are not in the number: it is what the brewer's own files put into every one of its prompts. No tokenizer is loaded: a tokenizer would be a dependency per model, and a notice only needs the order of magnitude.
- **A costly prompt.** A brewer whose estimate is above `COSTLY_PROMPT_TOKENS` (`src/cli/doctor.ts`), 8,000 tokens, gets a notice naming its file, the estimate and the threshold. 8,000 is about three times the largest default today (the Gauger with the test-design lens, under 3,000), so a prompt above it carries far more of its own text than Foedrum's brewers do, and is worth a look before every batch pays for it. The threshold is a constant in the code, changed by a pull request; a Brewery cannot set it.
- **Unused files.** When the files load, a Brewery brewer that no recipe in use names in a step, and a Brewery lens that no brewer in use names in a `lens:` input, get a notice naming the file. Only the Brewery's own files count. A default is shipped to every Brewery and cannot be dropped without replacing it (ADR 0098), so a notice about the four default lenses no brewer reads yet would only be noise. A step's `lens` still fails the load (ADR 0053); when it loads (#26), a lens a step names counts as used too.
- **What a Brewery file drops from its default.** For each Brewery file, recipe, brewer or lens, that replaces a default of the same name (`replacedDefaults`, `src/engine/recipe-files.ts`, by the rule `filesInUse` follows), doctor gives a notice that names both files, whether or not the files load. It lists the default's **headings** and **marked lines** that the Brewery's file no longer has, or says it keeps them all:
  - A heading is a Markdown ATX heading (`#` to `######` at the start of a line, at most three spaces in), by its text.
  - A marked line is a line, or a list item (`-`, `*`, `+` or a number with `.` or `)`), that starts with a bold phrase (`**…**`), by that phrase: the form the default brewers and lenses already give their rules, as the Gauger's `- **Stubs throw `not implemented`.**` and the lenses' `**Tests that cannot fail.**`. The bold lead names the rule; the text after it may be reworded without a notice.
  - Lines inside a fenced code block are neither. Two texts match when they are equal after trimming, collapsing runs of white space and ignoring letter case; the heading's level and the kind of list do not matter. A recipe has neither, so its notice only names the replacement.
  - A default that cannot be read is compared as having none.

## Consequences
- A maintainer sees what a brewer's own files cost per prompt, and which Brewery files are dead, before a batch runs, at no cost.
- A default author who wants a rule to be noticed when a Brewery drops it gives it a bold lead or a heading. A rule written as a plain sentence is not tracked; that is the price of not marking lines with a syntax of their own.
- The size line is a floor: a batch's prompt adds the order, the out docs and the contract. #283 reports the usage per brewer that the runs actually spent.
- A Brewery file that replaces a default always gets a notice, even when it keeps everything: replacing a default is a choice worth seeing, and a later default may grow a rule the copy lacks.

## Alternatives considered
- **A problem instead of a notice.** A costly prompt or a dead file does not stop a brewer; failing doctor on it would teach people to ignore the exit code.
- **Counting tokens with a tokenizer.** A dependency per model family for a number whose job is to say "large"; the 4-bytes estimate is good enough for a threshold.
- **A marker syntax of its own (`<!-- required -->`, a frontmatter list of required lines).** It would need adding to every default and keeping in sync with the text; the bold lead is already there and already reads as "this is a rule".
- **A text diff of the whole default.** Every rewording would show, and a long diff hides the one rule that went.
- **Notices for unused defaults.** The Brewery can do nothing about them but replace them; they would show on every Brewery.
