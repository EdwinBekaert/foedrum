# 0435. A driver moves an unstarted attempt's deadline on, a round that dismisses every finding needs no commit, and a brewer may `git rm`

Date: 2026-11-27 · Status: Accepted · Amends [0074](0074-git-commit-grants-fixed-git-rules-and-done-needs-a-commit.md) (a `done` with no commit succeeds when the brewer a findings route brought back dismissed every finding, and `git.commit` grants `git rm` too) and [0055](0055-a-step-waits-for-the-lease-of-its-abandoned-attempt.md) (a deadline that passes while no driver runs no longer makes its batch Stuck: the driver moves it on when it first takes the batch), and uses the rule of [0202](0202-pause-and-continue-hold-an-order-or-the-whole-brewery-at-its-next-convenient-point.md) (`step.rescheduled`) once more. Within [0062](0062-brewers-never-allow-git-with-no-fixed-subcommand.md): `git rm` has a fixed subcommand and never pushes.

## Context
Three batches went Stuck on 2026-11-19 for something that was not a failure (frictions 7, 34 and 35 of that day).
- **A deadline ran out before anything started.** The deadline of an attempt is set when it is scheduled. `foedrum recipe` scheduled `survey` with a deadline 20 minutes on, and `foedrum serve` started three hours later: its first tick made both batches Stuck with `deadline passed at survey`, though no attempt had started. ADR 0055 called this intended for a wait for a lease, and said a step's deadline that passes while no driver runs does the same; a step that no driver could start had no chance to meet its deadline.
- **A round that dismisses every finding was refused.** The security Taster of an exit run approved with one minor finding; the round back to the Cellarman dismissed it with a reason and committed nothing, and the runner refused the `done` as the divergence of ADR 0074. The tasting design says the brewer a findings route brings back may record `dismissed` with a `why`; a dismissal changes no code.
- **A brewer could not delete a file.** A Taster's finding asked to delete an empty test file; a brewer that commits runs only `git status`, `git add` and `git commit`, and Claude Code has no tool that deletes a file, so the Cellarman ended blocked on its environment.

## Decision
- **A driver moves the deadline on when it first takes the batch.** At each tick, before the supervisor's and again before the drive, a driver that takes a brewing batch with an attempt scheduled and not started, and has not driven the batch since it started, gives that attempt a new deadline from its step, as if just scheduled, through `step.rescheduled` (`rescheduleWaiting`, which a continue and a reopened usage window use already: it gives nothing to a batch a pause holds, whose continue does it). It does so once per batch and driver: an attempt scheduled later, in a batch the driver drives, keeps the deadline it was scheduled with, and so does a batch another driver holds, which is the one that takes it. The command is `take`.
- **I1 still holds, and I5 and the lifecycle say the rule.** A brewing batch has a deadline throughout; the new deadline is the one a step has when scheduled. A started attempt keeps its deadline, which still passes when it runs too long. The wait for the lease of an abandoned attempt (ADR 0055) is not changed: a driver that drives a batch has taken it, so the deadline of an attempt scheduled in it keeps running through that wait.
- **A done with no commit succeeds when every finding is dismissed.** For an attempt a findings route brought back, `limits` gives the step whose route it was and the findings of its route input, each at its place, and the step that found it when it is not the routing one (the other children of the group's round, ADR 0349). A `done` with no commit then succeeds when its out doc holds, for each of those findings, its own disposition `dismissed` or `pre-existing` at the finding's place (file and line, none for the change as a whole) and for the same step (a disposition that names no step is the routing step's). Each disposition answers one finding. A finding with none, or one marked `fixed` (which says a commit exists), or a route with no finding, leaves the divergence of ADR 0074 as it was. The out doc is the attempt's output, as any `done`'s. A commit that was made counts as before, and so do the rewritten start and an uncounted answer, which come first.
- **A brewer that commits may `git rm`.** `git.commit: true` grants `Bash(git rm *)` beside `git status`, `git add` and `git commit`, in that order, and the fixed system prompt names it with a line to remove a tracked file with it and commit the removal. It has a fixed subcommand and never pushes (ADR 0062).
- **The default Cellarman says both.** Its instructions tell it to remove a tracked file with `git rm` and that a round that dismisses every finding ends done with no commit; its version is raised.

## Consequences
- A driver that starts after a long stop no longer makes every batch with an unstarted attempt Stuck; each attempt gets its full deadline from the moment a driver took it. A person who stopped a driver for hours loses no batch for it.
- A batch whose attempt could not start for a reason other than the driver's absence (a lease wait, a closed usage window) is as before: the deadline runs, or the window holds it (ADR 0206).
- Each driver start adds one `step.rescheduled` per batch it takes with an unstarted attempt, and one at the first tick of a fresh batch.
- A dismissal is trusted as before: the next round's Taster checks the evidence of its `why` and may contest it once (ADR 0204).
- A brewer can remove any tracked file of its worktree; the removal is a commit, scanned for secrets as any (ADR 0187).

## Alternatives considered
- **Start the deadline when the attempt starts.** A step could wait for ever with no deadline, which I1 forbids; the wait for a lease and a usage window would have none.
- **Reschedule every attempt when it is scheduled.** Each step would carry a second event, and the deadline of an attempt that waits for a lease would be moved on again and again, so that it never passed.
- **Let the supervisor move a deadline that passed before its first tick.** The supervisor cannot tell a driver that never ran from one that has not yet ticked, and it would hold an attempt whose deadline passed while a driver ran.
- **Succeed a `done` with no commit whenever it dismisses something.** A finding left with no disposition would be dropped without a word.
- **Let the engine delete the file a brewer names.** One more effect outside the ledger, for what `git rm` and a commit record as a change of the batch.
