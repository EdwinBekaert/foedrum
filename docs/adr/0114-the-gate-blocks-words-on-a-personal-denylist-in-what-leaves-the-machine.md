# 0114. The local gate blocks words on a personal denylist in what leaves the machine

Date: 2026-10-22 · Status: Accepted · Amends [0045](0045-the-local-gate-reads-commands-as-the-shells-would.md) (what the gate reads before a push and before the texts gh sends) and [0104](0104-the-gate-checks-the-tree-a-command-pushes.md) (what runs in the tree a push comes from) · Amended by [0132](0132-the-gate-reads-what-gh-posts-against-the-personal-denylist.md)

## Context
Since #48, sessions push branches, open pull requests and post comments without a person reading each one first, and the repository is public. Some words must never appear there: a client's name, an employer's internal project, a colleague's handle. A rule in a prompt is not enough, and the list cannot be in the repository either: even a hash of a short name is confirmed by a guess (#131). The local gate ([ADR 0045](0045-the-local-gate-reads-commands-as-the-shells-would.md)) already reads every `git push` and `gh` call a session makes, so it is where such a list can hold.

## Decision
- **The list is the user's, outside the repository.** It is the file `FOEDRUM_DENYLIST` names, or else `~/.config/foedrum/denylist.txt` (`os.homedir()`), on every platform: one path to write down on Windows, macOS and Linux, which Git Bash's `~` reaches too. `%APPDATA%` would fit Windows' conventions, but the list is a developer's file next to their shell's configuration, not an application's state, and one path is easier to document and check. One entry per line; blank lines and lines starting with `#` are skipped. Nothing about the list is committed, logged or printed: not its words, not their count, not a hash.
- **Matching.** Text and entries are put in Unicode's compatibility form (NFKC) and lowercased. An entry keeps only its letters and digits (`Example-Corp` is `examplecorp`). Text is split into words at everything that is not a letter or a digit, and inside identifiers at camelCase (`fooBar`, `HTTPServer`), and between letters and digits. An entry matches a word, or several words in a row joined together, on one line: `examplecorp`, `ExampleCorp`, `example_corp`, `example-corp.config`, `exampleCorpClient` and `Example Corp` all match `examplecorp`; `examplecorporate` and `notexamplecorp` do not. Joining across spaces may block an innocent phrase now and then; that fails closed.
- **What a push sends is scanned.** Before `git push`, after the detached-HEAD check and before `npm run check` (both in the tree the push comes from, ADR 0104), the gate reads the commits `HEAD --not --remotes=<remote>`: those the tracking refs of the remote the push goes to do not have, which is what a push of the branch to it can send. Another remote's refs (a private mirror) say nothing of what this one has. The remote is the one the command names (its first operand, else `--repo`); a push that names none goes to the current branch's push remote, by name, as git works it out (`git for-each-ref --format=%(push:remotename)`: `branch.<name>.pushRemote`, `remote.pushDefault`, `branch.<name>.remote`), or else to `origin`, as git does. A remote's name may hold a slash, so it is never cut out of a ref. A command that pushes to more than one remote blocks while a list is set: one scan per command keeps the git calls within one deadline budget. A remote computed at run time, or given as a URL or a path, blocks the push while a list is set: it has no tracking refs to read against, and the line says to name the remote. For each, it reads the author's and committer's names and emails, the message, the path of every file it changes and the lines it adds (`git log --patch --unified=0`, without context). Removed lines are not read: the remote has them. A merge is read as a combined diff (`--diff-merges=dense-combined`), and a line is read only when it is added against every parent, so the lines a merge adds of its own (a conflict resolution) are read, but not a line one parent brought: that parent's commits are read on their own, or are on the remote already. Only git's stdout is read: stderr arrives in chunks that need not end a line, and could split a line or end a hunk early. git reads the commits as stored and prints them plainly: `--no-replace-objects`, `core.quotePath=false`, `--no-ext-diff --no-textconv --no-color --no-renames --no-relative --no-mailmap`, and binary files as text (`--text`), so a word in a file's plain bytes is found; a word inside compressed bytes is not.
- **What gh sends is to be scanned too**, in a change of its own split off #131 (the push scan and doctor's line come first, and until then the gate does not read gh's texts): the title and body of `gh pr create|edit|comment` and `gh issue create|edit|comment`, given inline (`-t`/`--title`, `-b`/`--body`) or from a file (`-F`/`--body-file`, read from the directory gh runs in), and the `title` and `body` fields of a `gh api` call that writes (`-f`/`-F`/`--field`/`--raw-field`), inside `bash -c`, `pwsh -Command` and every other command the gate reads (ADR 0045).
- **A hit blocks, and names the place, never the word.** The command is blocked with one line that names up to ten places and counts the rest: `commit 1a2b3c4 notes/plan.md:12`, `commit 1a2b3c4 message line 3`, `commit 1a2b3c4 author`, `gh pr create --body line 2`. A file whose path holds a word is named `a file whose path holds a denied word`, in the place of the path and of its lines. Hook output reaches the session's transcript, so the word would be in it if the line named it.
- **What the gate cannot read fails closed, when a list is set.** A list `FOEDRUM_DENYLIST` names that cannot be read, or a default file that is there but cannot be read, blocks every push (and, with the gh change, every gh text), saying so. A git log that fails, times out or passes the runner's 4 MiB of output (ADR 0035) blocks the push. With the gh change, a title or body computed at run time (a variable, a substitution), a body file the gate cannot read, a `gh api` field read from a file (`body=@file`) and `gh api --input` block the command, with a line that says to give the text inline or from a file the gate can read.
- **Deadlines.** Each git call (the push remote's name and the two logs) gets 15 s, so the three fit between the HEAD check's 10 s and `npm run check`'s 540 s under the hook's 600 s.
- **No list, no change.** Without `FOEDRUM_DENYLIST` and without the default file, the gate runs no git call and reads no text for it, and behaves as before. `foedrum doctor` prints one line that says whether a denylist is set, and where, and that the gate scans what `git push` sends, never its words or how many there are.
- **The pure core is `scripts/denylist/core.ts`** (ADR 0021): the list's parsing, the splitting, the matching and the reading of git's output, tested with fixture words only. The shell, `scripts/denylist.ts`, reads the list and runs git through the runner. No test reads the real list or the user's home: the list's path and text are injected.

## Consequences
- A word on the list stays on the machine, whether a session or a person typed it, as long as the push (and, with the gh change, the text) goes through a Claude Code session's gate. A push from another terminal is not checked, as for `npm run check`.
- Each push with a list set costs two `git log` calls in the tree it comes from, and a `git for-each-ref` when it names no remote; without a list, none.
- A file that already holds a listed word on the remote is not blocked again, unless a pushed commit adds a line with it. A merge of `origin/main` whose combined diff is clean adds nothing to read.
- The scan reads the commits of `HEAD`. A push of another branch (`git push origin other`) reads the wrong commits, as `npm run check` checks the wrong tree (CLAUDE.md). So do `--all`, `--tags`, `--follow-tags` (or `push.followTags`) and a refspec naming another ref: tags and their messages are not read. Push the branch of the checkout you changed, as the gate expects for the check.
- A stale tracking ref of the remote the push goes to makes the scan read more commits, never fewer: a commit that is on the remote but not yet fetched is read again.
- A list entry spread over a word boundary in plain text (`Example Corp`) matches, and so may an unlucky phrase whose words run together into an entry. The remedy is to rephrase; the gate never says which entry matched.

## Alternatives considered
- **Commit hashes of the words, so the list can be shared:** a short name's hash is confirmed by guessing it (#131).
- **Scan `git diff origin/main...HEAD` only:** a commit that adds a word and a later one that removes it leave a clean diff, and the push still sends both (ADR 0079 chose per-commit for the same reason).
- **Fail closed on binary files, as the secret scan does (ADR 0079):** every push of an image would stop while a list is set. Reading their bytes as text finds a word in plain metadata, and a compressed word is no more readable by failing.
- **First-parent diffs for merges:** a merge of `origin/main` would read everything main brought in, already public, and a large one passes the output limit and blocks every push after it.
- **`%APPDATA%\foedrum\denylist.txt` on Windows:** fits the platform, but gives the list two homes to document, and Git Bash sessions write `~/.config` paths anyway.
