# 0431. Brett's mutants on Node run only the test files that reached their line

Date: 2026-11-27 · Status: Accepted · Amends [0313](0313-the-engine-runs-brett-s-mutants-in-scratch-trees-against-a-fresh-baseline.md) (a mutant's run is no longer always the whole `test` check, and its verdict no longer compares every test of the baseline); applies [0303](0303-brett-s-mutants-run-only-the-test-files-that-cover-their-line.md)'s per-file coverage to the engine's own mutant step

## Context
The mutant step runs a baseline and then each valid mutant, one at a time, each as the repository's whole `test` check ([ADR 0313](0313-the-engine-runs-brett-s-mutants-in-scratch-trees-against-a-fresh-baseline.md)). On #1161, six full unit-suite runs took about 15 minutes for mutants on five lines, and all five were killed (#1176).
Nothing recorded says which tests ran a line. Green's coverage is one merged report with line counts, Node's lcov names no test, and `--experimental-test-coverage` "cannot tell which test file ran a line" ([ADR 0303](0303-brett-s-mutants-run-only-the-test-files-that-cover-their-line.md)). A repository's `checks` had no way to run only some test files.
[ADR 0303](0303-brett-s-mutants-run-only-the-test-files-that-cover-their-line.md) solved this for `/brew-review` on Node: a run with `NODE_V8_COVERAGE` leaves one V8 coverage file per test file, because the test runner runs each test file in a process of its own.

## Decision
- **The baseline records which test files reach each line, on Node.** The mutant step still runs its own baseline on an untouched tree, which sets the three-times limit as before ([ADR 0313](0313-the-engine-runs-brett-s-mutants-in-scratch-trees-against-a-fresh-baseline.md)), and green does not stand in for it. When the repository names `testFiles` (below), the baseline runs the whole `test` check with `NODE_V8_COVERAGE` set to a folder of its scratch tree, only for the test check, not for the setup. `readNodeCoverage` (`src/checks/node-coverage.ts`) reads the folder after the run: each record's test file is the first script of the tree it compiled, the file its process was started on, and the record holds the ranges of every script of the tree it loaded.
- **`checks.testFiles`, a command that runs a list of test files.** A new optional field beside `test` and `testChanged` in `foedrum.jsonc`: a command, with its platform overrides, whose every line holds `{files}`, replaced by the test files' paths with a space between them (`testFilesLine`). It needs a `test` check. Foedrum's own Brewery sets it to its `node --test` line.
- **A line ran in a test file's process** by [ADR 0303](0303-brett-s-mutants-run-only-the-test-files-that-cover-their-line.md)'s rule: one of its non-blank characters lies in an innermost range with a count above zero, the offsets those of the text after a byte order mark (`reachOf`, `src/checks/mutant-reach.ts`). Unlike the review, the engine has no list of the file's own tests: the coverage alone decides.
- **Each mutant runs only the test files that reached its line.** They are passed sorted to `testFiles`, in a fresh scratch tree as before, and the run says which files it ran. When no test file reached the line, the mutant survives without a run: no test could fail because of it, and a blocking step blocks on it as on any survivor ([ADR 0319](0319-brett-s-survivors-are-listed-where-findings-are-and-a-blocking-brett-step-sends-them-back.md)).
- **What the coverage cannot tell runs the whole check, as today.** A repository that names no `testFiles`, a language other than Node (no process wrote a record), a coverage that cannot be read or that two records name one test file in, the text of a mutant's file that was not read, a line past the end of its file, and a test file name that is not letters, digits and `. _ / @ + -` (the list is one command line, so a space or a line break could split a name or forge a command) each send every mutant to the whole check.
- **The verdict compares the files that ran.** `judgeRun` takes the run's test files and compares the run with the baseline's tests of those files only, found by the file each test's report places it in (an absolute path of a scratch tree matches by its end, after a folder), so a test missing from a partial run is no longer read as a kill ([ADR 0040](0040-brett-covers-scripts-and-kills-need-a-failing-test.md)). A baseline test the report places in no file is left out of a scoped run. A module that passed no test in the files that ran is `notJudged`. A run of the whole check compares every test, as before.

## Consequences
- A mutant in a widely imported file runs a handful of test files, and one that no test file reaches runs none. The baseline is slower with coverage (about half again, [ADR 0303](0303-brett-s-mutants-run-only-the-test-files-that-cover-their-line.md)'s measure), once per attempt.
- A mutant killed only by a test that does not run its line is not lost: such a test can fail only through something the mutant changed that a test running the line also sees ([ADR 0303](0303-brett-s-mutants-run-only-the-test-files-that-cover-their-line.md)).
- A node process a test starts writes a record of its own, named by the script it ran. A line only that child runs is reached by that script, not by the test that started it, so the mutant runs the script as a test file, which does not test it. The review's own-test rule (`ownTestsOf`) is Foedrum's file layout and is not carried over.
- The offsets are read against the file as git holds it at the commit, since a scratch tree is gone when its run ends; a repository that checks files out with other line endings than the commit's holds would shift them. Not measured here.
- Keeping verdicts after a Taster's round is a separate issue, built on this one.

## Alternatives considered
- **Per test, not per test file:** the test runner gives no coverage per test case, and the runs take test files ([ADR 0303](0303-brett-s-mutants-run-only-the-test-files-that-cover-their-line.md)).
- **Green's coverage as the baseline:** it is one merged report, and a mutant's three-times limit needs a baseline that ran as the mutants do on an untouched tree.
- **A `testFiles` that is always Node's:** a repository on another runner would then run `node --test` over its files. A repository names its own command, and one that names none runs the whole check.
- **Import analysis for the test list, as `testsFor` does for the review:** the engine would need each language's import rules; the records of the baseline say which files ran, whatever imported them.
