# What Foedrum changes

Everything Foedrum writes, on your machine, in the Brewery and on GitHub, and how to take it away.
"A driver" is `foedrum serve`, `foedrum brew` or another command that brews a batch; "the work root" is `~/.foedrum/<owner>.<name>` of the Brewery, or the `workRoot` in the Brewery's `.foedrum/local.jsonc`.
Remove what the work root and `.foedrum/` hold only while no driver runs.

| Where | When | What | Why | To remove |
|---|---|---|---|---|
| Your machine | Installing | Nothing yet: the npm package is not published (`"private": true`), so neither `npm install` nor `npx` can fetch it, and you run Foedrum from a checkout, as above. The package has no install scripts. | | Delete the checkout. |
| Your machine | `foedrum init`, outside a Brewery, after a yes to creating one | A clone of the Brewery repository, new or one GitHub had that you said is your Brewery, in the folder you gave: by default the folder init runs in, or `foedrum-brewery` beside the repository it runs in. Never inside another repository. | [ADR 0207](adr/0207-foedrum-init-creates-the-brewery-s-repository-labels-the-targets-and-pushes.md), [ADR 0393](adr/0393-foedrum-init-finds-where-it-is-and-asks-where-the-brewery-goes.md) | Delete the folder. |
| Your machine | `foedrum init` from a checkout only, after you pick a folder (Enter picks the first) | The `foedrum` command in a folder on your PATH inside your home: a `foedrum` script, and on Windows `foedrum.cmd` beside it, each with a line saying init wrote it. It never edits your PATH or a shell profile, and never replaces a file it did not write. From the installed package it writes nothing and, when no `foedrum` but npx's own is on your PATH, says to run `npm install --global foedrum` or `npx foedrum <command>`. | [ADR 0210](adr/0210-foedrum-init-writes-the-foedrum-command-into-a-user-folder-on-the-path.md), [ADR 0212](adr/0212-foedrum-init-takes-every-answer-as-an-option-and-foedrum-init-asks-them-in-a-session.md), [ADR 0390](adr/0390-foedrum-init-offers-the-shim-only-from-a-checkout.md) | Delete the files. |
| Your machine | Each driver | In the work root: `brewery.json`, a lock per driver in `drivers/`, the state branch's worktree `state/` and its `state.lock`, an empty `no-hooks/`, each brewer's settings and prompts in `attempt-settings/`, a checkout of each target repository per read-only attempt of a Brewery order in `brewery-orders/`, and per target repository its clone (`clone.git`, when its `source` is `managed`), the attempts' worktrees in `attempts/` and short-lived git folders in `git-dirs/`. | [ADR 0037](adr/0037-attempt-worktrees-in-the-engine-and-driver-locks.md), [ADR 0012](adr/0012-worktrees-from-local-clones.md), [ADR 0301](adr/0301-a-brewery-order-s-read-only-attempt-reads-every-repository-in-a-checkout-of-each.md) | A batch's worktrees and settings go when it ends, or at the next start, except a Stuck batch's, one in use and one with changes; the rest stays: delete the work root. |
| Your machine | Each driver, for a target whose `source` is `local` | In your own clone of that target: a worktree record and a branch `foedrum/<batch>/<step>/<n>` per attempt, `git fetch --prune origin`, and git objects. A branch with commits no push sent is kept, and `foedrum status` lists it. | [ADR 0084](adr/0084-a-batch-s-commits-end-in-a-pull-request-or-on-a-kept-branch.md) | The rest goes with the batch; `git branch -D` a kept branch, as `foedrum status` says. |
| Your machine | While a brewer runs | No file: a helper process keeps the machine awake, and ends a minute after the last attempt or with Foedrum. | [ADR 0195](adr/0195-brew-and-serve-keep-the-machine-awake-while-an-attempt-runs.md) | `"keepAwake": false` in `foedrum.jsonc` or `.foedrum/local.jsonc`. |
| Your machine | Each brewer | Claude Code keeps the brewer's session under `~/.claude` (or `CLAUDE_CONFIG_DIR`), as for any session; `foedrum resume` opens it. | [ADR 0126](adr/0126-foedrum-resume-opens-a-finished-attempt-s-session-in-its-worktree.md) | As for your other Claude Code sessions. |
| Your machine | Each check step, on macOS | A `foedrum-check-*` folder in the system's temporary folder, the check's home, removed after the check. | [ADR 0076](adr/0076-check-steps-run-in-an-os-sandbox-with-no-network.md) | Nothing to do. |
| The Brewery | `foedrum init` | `foedrum.jsonc`, `models.jsonc`, `.gitignore` (with `.foedrum/`) and `.claude/settings.json` (with the plugin `foedrum@foedrum` on), at the Brewery's top, from any folder in it, or in the folder init cloned it into; never in a repository without `foedrum.jsonc` that holds files. A file already there changes only after you agree. | [ADR 0199](adr/0199-foedrum-init-writes-a-brewery-s-files-in-its-clone.md), [ADR 0393](adr/0393-foedrum-init-finds-where-it-is-and-asks-where-the-brewery-goes.md) | Delete or revert them. |
| The Brewery | Installing the plugin | What `claude plugin install` records, and, for your user, the marketplace `claude plugin marketplace add` records. The plugin's skills only run `foedrum <command>`: no hooks, settings or servers. | [ADR 0125](adr/0125-the-foedrum-plugin-is-markdown-skills-that-run-the-terminal-with-via-plugin.md) | `claude plugin uninstall foedrum@foedrum`, then `claude plugin marketplace remove foedrum`. |
| The Brewery | Each driver | `.foedrum/index.db` (with `-wal` and `-shm`), the event store; a local branch `foedrum/state` with its worktree in the work root. | [ADR 0024](adr/0024-state-branch-layout-outbox-and-divergence.md) | Delete `.foedrum/index.db*`; `git worktree remove` the state worktree and `git branch -D foedrum/state`. |
| GitHub, the Brewery's repository | `foedrum init`, for a name GitHub does not have yet | The Brewery repository, private unless you answer public, created only after every question. | [ADR 0207](adr/0207-foedrum-init-creates-the-brewery-s-repository-labels-the-targets-and-pushes.md) | Delete the repository. |
| GitHub, the Brewery's repository | `foedrum init`, after a yes | A commit "Set up the Brewery with foedrum init", pushed with any earlier commits GitHub does not have yet, which init lists first. | [ADR 0207](adr/0207-foedrum-init-creates-the-brewery-s-repository-labels-the-targets-and-pushes.md) | Revert the commit. |
| GitHub, the Brewery's repository | Each driver | The branch `foedrum/state`, never forced. An issue per claimed target issue, reopened for its next batch. A status comment per batch, edited in place. A plan's comment and its sub-order issues, linked as sub-issues and blocked by each other. An issue per pre-existing finding once the pull request merges. A comment and a close when a batch's pull request merges. Labels on these issues: `foedrum:ordered`, `foedrum:brewing`, `foedrum:conditioning`, `foedrum:awaiting-approval`, `foedrum:awaiting-answer`, `foedrum:stuck`, `foedrum:awaiting-merge`, `foedrum:sub-orders`, `recipe:<name>`, `foedrum:sub-order`, `needs-refinement` and `foedrum:pre-existing`. | [ADR 0024](adr/0024-state-branch-layout-outbox-and-divergence.md), [ADR 0072](adr/0072-the-status-comment-edits-as-revisions-in-the-ledger.md), [ADR 0154](adr/0154-lane-labels-on-the-order-s-issue-and-the-status-comment-s-path-line.md), [ADR 0285](adr/0285-an-approved-plan-becomes-brewery-sub-issues-through-the-ledger.md), [ADR 0356](adr/0356-a-pre-existing-finding-becomes-a-brewery-issue-once-the-pull-request-merges.md) | Foedrum deletes nothing here but a lane or recipe label it replaces on an issue: delete the rest by hand. |
| GitHub, each target repository | `foedrum init`, after a yes | The label `foedrum:brew`. | [ADR 0359](adr/0359-the-intake-takes-an-issue-only-when-someone-in-users-added-its-labels.md) | Delete the label. |
| GitHub, each target repository | A claimed issue | The ref `refs/foedrum/claims/issues/<n>` on an empty commit, the label `foedrum:claimed`, your gh account as assignee, and a comment when the claim is taken and when it is released. | [ADR 0043](adr/0043-target-repository-issues-as-a-work-queue-claimed-by-a-ref.md) | The ref and the label go when the claim is released; the assignee stays, so no other Brewery takes the issue: unassign it by hand. |
| GitHub, each target repository | Each batch | A branch `foedrum/<brewery owner>.<name>/<batch>/…`, never forced. A pull request, opened as a draft and marked ready, or back to a draft, by its merge brief, whose body Foedrum updates. Its merge brief and base-check comments, an older brief hidden as outdated. | [ADR 0167](adr/0167-a-brewed-pull-request-follows-one-layout-and-opens-as-a-draft-unless-every-taster-approves.md), [ADR 0350](adr/0350-a-brewed-pull-request-is-a-draft-until-its-merge-brief-and-the-next-line-follows-the-brief.md) | Foedrum never deletes the branch: turn on GitHub's "Automatically delete head branches", or delete it by hand. |
