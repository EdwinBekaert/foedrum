# npm run demo

`npm run demo` makes a scratch Brewery and target repository with bare remotes in `.foedrum/tmp/demo/` (removed at the start of the next run), one order brewed with the demo Brewery's own recipe `nip-parallel` (Nip's steps from `defaults/`, its taste step a `parallel` group of four lens steps, whose findings all go back along the group's `onFindings` route to `implement`, once, where Nip's go back twice at most ([ADR 0354](../../docs/adr/0354-every-finding-of-a-taster-goes-back-along-one-on-findings-route.md)); after the group an advisory `mutants` step, whose scripted Brett proposes two mutants of the line the fix leaves for the engine to run in scratch trees: one killed, one surviving and listed under the status comment's Findings, [ADR 0319](../../docs/adr/0319-brett-s-survivors-are-listed-where-findings-are-and-a-blocking-brett-step-sends-them-back.md)) by the Nip fixture's scripted Maltster, which commits the target's test map (one module, its TAP report, coverage `none`) for the survey's check to run the tests against, Gauger, Cellarman and Finer and the demo's four Tasters, which play a tasting loop: round 1's correctness Taster asks for changes and the other three approve with a finding each, the Cellarman's third attempt fixes correctness's finding and records it `fixed` and dismisses the other three with a reason, and round 2 approves with no finding (ADR 0193, ADR 0354) through `foedrum serve`'s own Cellar, killed mid-attempt with SIGKILL and started again, until the batch is on tap with one pull request and one status comment on an in-process fake code host; then a second order brewed by `foedrum brew` in a process of its own, `foedrum resume`'s line for the Cellarman's attempt, printed and never opened, and `foedrum replay`; then a third order mashed: `foedrum mash` stops at the scripted Innkeeper's question, the demo runs `foedrum answer` to choose `mash`, and `foedrum brew` drives the scripted Brewmaster to a plan of two sub-orders, which three scripted Tasters review side by side ([ADR 0321](../../docs/adr/0321-mash-and-decoction-review-a-plan-through-the-plan-lenses-apart.md)), the naive reader's note sending it back once for a corrected plan, which waits Stuck for its review, with its plan comment (ADR 0232, ADR 0275, [ADR 0283](../../docs/adr/0283-npm-run-demo-mashes-a-third-order-to-a-plan-waiting-for-its-review.md)).

- It walks through twelve steps (the demo's own diagnosis, the order, `foedrum status` as the batch moves, the kill and the restart, the red proof and the failed check, the pull request and the status comment, on tap, `foedrum lenses` (ADR 0221), `foedrum brew`, `foedrum resume`, `foedrum replay`, `foedrum mash`), each with what to look for, and waits for Enter between them; `--no-pause`, or input that is not a terminal, goes straight through.
- Three seams are the demo's own (the brewer, the code host, the wait that ends a life); every git it starts reads only `<scratch>/gitconfig` (`GIT_CONFIG_GLOBAL`, `GIT_CONFIG_NOSYSTEM=1`): the demo's identity, no signing, and an `insteadOf` that sends `https://github.com/demo/web.git` to the scratch remote and every other GitHub URL to a path that does not exist, so serve's own push and fetches stay local.
- `npm run demo -- ladder` runs the ladder instead, in the same scratch folder ([ADR 0294](../../docs/adr/0294-npm-run-demo-ladder-walks-an-order-across-two-repositories.md)): `scripts/demo/ladder.ts` (its steps and decisions, given the shell's processes), `ladder-brewers.ts` (a Brewmaster that plans from `lib/` and `web/` in its folder of checkouts, the default `mash`'s three Tasters, which approve, and Cellarmen that change `demo/lib` and bump `demo/web` to the tag its `release` input names) and `ladder-cellar.ts` (one life of the Cellar: `plan`, `lib`, `web` or `close`, each ended on a condition read from the store). One order labelled `recipe:mash` across `demo/lib` and `demo/web` (aliases `lib` and `web`, no checks, recipe `ladder`), in fourteen steps from its plan to its close; between lives the shell merges each pull request with `--no-ff` and plays the library's CI (`package.json` at 1.4.0, tag `v1.4.0`, a release) on the fake code host.
- It imports the tests' fakes from `test/helpers/`, so it stays a script and the package ships only `src/`, `defaults/` and `schemas/` ([ADR 0097](../../docs/adr/0097-npm-run-demo-is-a-script-on-serve-s-seams-with-the-tests-fakes.md), [ADR 0139](../../docs/adr/0139-npm-run-demo-brews-with-nip-and-shows-foedrum-brew-and-foedrum-resume.md), [ADR 0185](../../docs/adr/0185-npm-run-demo-tastes-through-a-parallel-group-of-three-lenses.md), [ADR 0193](../../docs/adr/0193-npm-run-demo-shows-a-tasting-loop.md)).
