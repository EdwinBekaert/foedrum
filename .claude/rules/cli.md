# The foedrum commands

What `node src/cli/main.ts <command>`, the `foedrum` program from a checkout (the package's `bin` is the JavaScript `tsc` emits, `dist/cli/main.js`, ADR 0377), runs: `serve` (the Cellar, until Ctrl+C; ADR 0063), `doctor`, `init [--<question> <answer>]... [--no-input]` (a Brewery's files from a few questions, each answerable by its option, `--no-input` refusing a question no option answers, ADR 0212; outside a clone it creates and clones the Brewery's repository, then the intake labels after asking, a commit and push after asking, the `foedrum` command in a user folder on the PATH after asking, and doctor; ADR 0199, ADR 0207, ADR 0210), `status [<order>] [--watch]` (a board of the live batches on a terminal; ADR 0188; with an order, its batches and its sub-orders' with planning and brewing tokens, [ADR 0295](../../docs/adr/0295-foedrum-status-order-shows-planning-tokens-apart-from-brewing-tokens.md); planning is the attempts of a recipe of type `mash`, by the type its choice recorded, [ADR 0365](../../docs/adr/0365-a-recipe-has-a-type-mash-or-brew.md)), `stuck`, `brewers` (each brewer's attempts, outcomes, Stuck batches and tokens; ADR 0159), `lenses` (each lens's rounds, findings and how they ended, the rounds its steps took to pass, and its tokens; ADR 0221), `handover <issue>` (what a batch's brewers handed over, each line a proposal a model wrote, kept on `step.finished` and in no later prompt; [ADR 0340](../../docs/adr/0340-a-brewer-s-handover-is-kept-as-a-proposal-and-reaches-no-later-prompt.md)), `replay <issue>`, `resume <issue> [<step>[#<n>]]` (a finished attempt's session in its worktree, ADR 0126; on a running batch, a takeover that continues its step's session until its out doc, ADR 0127), `brew <issue> [--as <name>] [--take] [--new-window]` (one batch as a driver of its own, ADR 0123, owned by `--as`, else the Claude Code session, else `terminal`, ADR 0259; of an on-tap batch it records its pull requests' ends and applies the release or close still due, with no intake, ADR 0336; an issue with no recipe label it routes to the Brewery's default recipe, `mash-in` unless `foedrum.jsonc`'s `defaultRecipe` names another of type `mash`, [ADR 0370](../../docs/adr/0370-foedrum-brew-runs-the-brewery-s-default-recipe-on-an-issue-with-no-recipe-label.md); on a terminal it opens an interactive step as a `claude` session in the foreground, and `--new-window` starts it in a new terminal window, ADR 0222), `mash <issue> [--as <name>] [--take] [--override]` (brew's driver routed to `mash-in`, until the Innkeeper's question, ADR 0232; `--override` asks again for an issue whose batch has a recipe, as `recipe` restarts it, refused while it is Brewing or its plan's sub-orders have not ended, [ADR 0374](../../docs/adr/0374-foedrum-mash-override-asks-the-innkeeper-again-for-an-issue-with-a-recipe.md)), `takeover <issue> [--as <name>]` (hand a batch to another driver; ADR 0124), `lauter <issue> [--as <name>]` (the plan of a batch Stuck as plan_review corrected with the Brewmaster in an interactive session: records the lauter, then brews the batch's issue as `brew --take` does, so the session opens on a terminal, and the batch waits for a review of the session's plan; [ADR 0286](../../docs/adr/0286-foedrum-lauter-corrects-a-plan-at-gate-1-in-an-interactive-session.md)), and the commands that change state (`retry`, `skip`, `answer`, `approve <issue>` (sign off the plan a batch Stuck as plan_review waits with, recorded by its digest; the batch goes on tap, [ADR 0281](../../docs/adr/0281-foedrum-approve-signs-off-a-plan-by-its-hash-and-puts-the-batch-on-tap.md)), `recipe <batch | issue> <recipe> <reason>` (by issue: an ended issue is ordered again with the recipe, under the same refusal as order, a Brewing batch refused until stop, and a person's choice labels the issue's latest, unended batch, ADR 0240; its due effects, the recipe label and the status comment among them, go out before it returns, through a driver of its own that drives nothing, ADR 0355), `rewind`, `cancel`, `order <issue>` (the first order of an issue, or an ended one's next, never while a Brewery issue on tap has a pull request with no recorded end, ADR 0339; a claimed order's Brewery issue orders its claimed issue, ADR 0240), and `pause [<order> | --all] [--by <time>] [--why <reason>]` and `continue [<order> | --all]`, ADR 0202; `stop <order> [--why <reason>]`, ADR 0205; `rank <order> [<place>] [--why <reason>]` (a place `n` or `first`), ADR 0208); `--help` lists them, and `--version` prints the version of Foedrum's own `package.json` (ADR 0377)
